## 已修复的功能缺陷

| 问题 | 影响与修复 |
| --- | --- |
| 仅识别 `flag{…}` | `moectf{…}`、`CTF{…}`、`DASCTF{…}` 无法进入候选流程。现在保留完整前缀和大小写，支持以 flag/ctf 结尾的赛事前缀。 |
| 报告依赖父 Agent 提交已验证完成 | 子项目已发现值，仍可能一直不报告。现在事实写入、子项目完成和事实发布时直接登记待人工确认候选；允许未验证候选进入人工审核。 |
| 只通知当前正在查看的项目 | 用户停留在列表或子项目页面会错过报告。新增全局待确认列表及常驻提醒，点击可进入父项目确认。 |
| 候选提示的模板字符串及中文损坏 | 修复候选数量表达式及相关提示；393 个页面表达式通过语法检查。 |
| 候选按大小写不敏感去重 | 大小写不同的 Flag 被合并。改为精确值去重；被拒绝的同一值不会反复上报。 |
| 提交说明可以自行充当验证证据 | 原先只需把值写进完成说明就能满足来源检查。现在必须匹配已保存事实或关联子项目证据。 |
| 有待确认候选时仍可普通完成 | 父项目不能通过不带证据的普通完成请求绕过待确认候选。 |
| 发布不存在的事实 | 子项目黑板发布接口现在先检查来源 Fact 存在，避免虚假引用。 |
| 旧库迁移删除项目 | `_ensure_orchestration_columns` 原先新增 kind 列后执行 `DELETE FROM projects`，连带丢失证据。已删除该清空逻辑，旧图保留；两项相关迁移测试通过。 |
| 重复录制覆盖历史快照 | 录制器现在以独占创建方式分配新的编号快照；latest/final 文件仍按其原有含义更新。 |

主要修改位置：`server/routers/projects.py`、`server/routers/intents.py`、`server/routers/orchestration.py`、`server/static/index.html`、`server/db.py`、`recording.py` 和父 Agent 提示词。

## 仍需处理的已确认问题

### P1：Codex 主机执行忽略已有沙箱设置

`cairn/src/cairn/dispatcher/workers/adapters/codex.py:44`、`:54`、`:83`、`:94` 固定传入绕过审批和沙箱的参数。该适配器没有实现旧测试要求的沙箱、网络允许列表和 JSONL 会话解析行为。目录 AGENTS.md 要求主机执行默认受沙箱约束，当前实现与此不一致。

本次未更换 Codex 执行契约，避免把整个运行适配器重写混入 Flag 修复。应单独统一 local/API 两种模式的配置、命令生成和会话恢复测试。

### P2：录制器会漏掉部分“数量不变”的内容变化

`cairn/src/cairn/recording.py:62` 附近的变化签名仅依据事件摘要，主要包含数量、任务和心跳；未完成项目的已有事实、Hint 或候选状态改变，而摘要保持不变时，不一定生成新快照。应以完整项目内容或稳定的变更版本号决定是否保存。

### P2：Docker 删除容器前没有持久化运行文件

`cairn/src/cairn/dispatcher/runtime/containers.py:98` 的完成清理在 remove 模式直接删除容器；孤儿清理也直接删除。容器内的会话和工作文件没有在这些路径上自动归档。当前 Windows API 模式的 stdout/stderr 持久化已验证，但不能据此宣称 Docker 模式也具备同等保留能力。

### P2：测试、文档与运行实现存在版本分叉

旧测试仍调用批量 `PUT /agents`，当前服务为单个 Agent 的 POST/PUT 接口；另有测试导入已不存在的 `RuntimeAgentProfile`、`decorate_worker_prompt`。部分主机和 mock 测试依赖 Linux Shell，在本机 Windows 环境无法直接运行。

这使“全量测试通过”目前无法作为版本发布门槛。应迁移过时测试，并为 Windows/POSIX 分别定义适用的运行测试。不能将这些失败全部归因于本次修改，也不能忽略其中的真实契约缺失。
